Java OOM

Java OOM

什么是 OOM

OOM（Out OfMemoryError）表示 JVM
无法继续为对象或资源分配所需内存，从而抛出java.lang.OutOfMemoryError。

需要区分： - OOM：JVM 内存申请失败，通常会抛出异常。 - JVM Crash：NativeMemory 等耗尽时，可能导致 JVM 直接退出。

常见 OOM 类型

类型 异常信息 常见原因

Heap OOM Java heap space 对象过多、内存泄漏

GC Overhead GC overhead limit exceeded GC 长时间回收效果极差

Metaspace OOM Metaspace 动态代理、类加载泄漏

Direct Memory Direct buffer memory Netty、DirectByteBuffer
OOM 使用不当

Native Thread unable to create native 线程数量过多
OOM thread

Code Cache OOM CodeCache JIT 编译缓存耗尽（较少见）

Native Memory Native Memory JNI、malloc、直接内存耗尽
OOM

OOM 的常见原因与场景

1. 创建对象过多

  • 一次查询大量数据加载到内存
  • Excel/CSV 一次性导出大量数据
  • 大 JSON 一次性反序列化

2. 内存泄漏

  • 静态集合长期持有对象
  • ThreadLocal 未 remove
  • Listener、回调未注销
  • Socket、文件流等资源未关闭

3. 缓存无限增长

  • HashMap/ConcurrentHashMap 无限制增长
  • 本地缓存未配置容量和过期策略

4. JVM 参数配置不合理

  • 堆空间过小
  • Metaspace 设置过小
  • Direct Memory 设置不足

如何防范 OOM

开发阶段

  • 分页查询、游标查询、流式处理
  • 控制对象生命周期
  • ThreadLocal 使用 finally remove
  • 缓存设置容量和过期时间
  • 合理使用线程池
  • 大文件采用流式读写

生产阶段

  • 合理配置 Xms/Xmx
  • 开启 HeapDump：
-XX:+HeapDumpOnOutOfMemoryError
-XX:HeapDumpPath=/dump
  • 开启 GC 日志
  • 建立 JVM 监控（Heap、GC、线程、Metaspace）
  • 缓存限流和容量规划

OOM 排查流程

  1. 查看异常日志，确认 OOM 类型。
  2. 收集 Heap Dump（jcmd/jmap）。
  3. 使用 MAT 分析：
    • Histogram
    • Dominator Tree
    • Leak Suspects
  4. 分析 GC 日志（GCEasy、GCViewer）。
  5. 使用 Arthas、jstack、jcmd 等定位代码。
  6. 修复问题并压测验证。

常用排查工具

工具 用途

jps 查看 Java 进程
jcmd JVM 综合诊断
jmap 导出 Heap Dump
jstack 查看线程栈
jstat 查看 GC
MAT Heap Dump 分析
Arthas 在线诊断
VisualVM JVM 监控
GCEasy GC 日志分析

常见修复方案

问题 修复方案

List 过大 分页、流式处理
缓存无限增长 容量限制、TTL
ThreadLocal 泄漏 finally remove
静态集合泄漏 有界缓存、及时清理
大文件处理 流式 IO
Metaspace OOM 修复类加载泄漏，调整参数
Direct Memory OOM 释放 DirectBuffer，检查 Netty 引用计数
Native Thread OOM 合理配置线程池

开发与生产的区别

维度 开发 生产

目标 复现与修复 快速止损、定位根因
数据量 小规模 海量数据、高并发
排查 Debug、日志 Dump、MAT、GC 日志、Arthas
配置 默认即可 OOM Dump、监控、GC 日志
修复 修改代码 修复+压测+监控验证
