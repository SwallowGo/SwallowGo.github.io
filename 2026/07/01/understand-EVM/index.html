JVM 与 EVM 对比

JVM

Java 编译流程：

JVM 负责：

  • 类加载
  • 内存管理
  • GC
  • JIT
  • 对象生命周期
  • 线程调度

Java 程序其实是在告诉 JVM：

“请按照这些规则执行程序。”

EVM

Solidity 编译流程：

Solidity 同样只是：

EVM 的高级语言。

真正执行程序的是：

EVM。

JVM 与 EVM 最大区别

JVM EVM
服务于一个应用程序 服务于整个区块链
有 GC 没有 GC
长生命周期进程 每笔 Transaction 独立执行
有线程 无线程概念
Heap 管理对象 无 Heap 概念
程序结束数据消失 Storage 永久保存
可无限执行 每一步消耗 Gas

最大的区别：

JVM 维护程序。

EVM 维护整个世界状态（World State）。

总结

  • EVM 是真正执行智能合约的虚拟机
  • World State 是 Ethereum 的全局状态数据库
  • Transaction 并不是发送后立即执行，而是进入 Pending Pool 等待打包
  • EVM 没有 GC，每笔交易都是独立执行环境
  • Storage 永久保存，因此成本极高
  • Gas 本质是计算资源计费模型，而不仅仅是手续费
  • mapping 并不是 HashMap，而是一种特殊的 Storage 映射规则
